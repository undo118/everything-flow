# 协作流程图工具 —— 立项讨论记录

> 与 Hermes Agent 的对话讨论整理
> 2026-06-01

---

## 一、痛点总结

现有流程图工具无法满足的核心需求：

| 痛点 | 描述 | 涉及工具 |
|------|------|----------|
| 节点无法表示"人+任务+文件" | 节点只能画形状加文字，不能结构化地绑定责任人、任务、上下游文件 | 全部 |
| 文件版本与节点脱钩 | 同一文件经不同人修改产生不同版本，无法在流程图中体现版本归属 | 全部 |
| 无法追溯责任链 | 出问题后无法沿文件流向逆推，定位哪个环节出了岔子 | 全部 |
| 无文件上下游全景图 | 缺乏类似 Obsidian Graph View 的网状图展示文件流转全貌 | 全部 |
| Markdown 渲染缺失 | 节点内无法渲染标题/列表/代码块/粗体等格式化文本 | 几乎全部 |
| 文件链接能力缺失 | 节点无法指向本地文件路径（如 `src/main.py:42`） | 全部 |
| AI 生成的排版不可控 | 箭头重叠、文字溢出，验收成本比手画还高 | Excalidraw 尤甚 |
| AI 控制门槛高 | 即使通过 MCP/skill 能生成，效果也无法保证 | Excalidraw |
| 协作 = 共享链接 | 没有"流程图即文档"的概念，无法 git 追踪变更 | 大部分 |
| 付费昂贵 | 好用的工具（Lucidchart, Whimsical, FigJam）免费额度有限 | 商业产品 |

## 三、核心定位

**不是 ——** 替代 Visio / draw.io 的通用画图工具

**不是 ——** 文件加工流水线（文件 → 程序 → 文件）

**而是 ——** 带文件追踪的**协作流程图**工具

> 用图形表示「人 → 任务 → 文件」的协作关系，节点内绑定责任人、任务描述、上下游文件及版本，箭头表示文件在人与人之间的传递。

### 3.1 核心功能定义

```
节点 = 一个人 + 他的任务 + 他经手的多份文件

  ┌──────────────────────────────────┐
  │  人 B                            │ ← 责任人
  │  任务：撰写分析报告               │ ← 任务描述
  │                                   │
  │  输入                              │
  │    ← 人A: 数据汇总.xlsx            │
  │    ← 人D: 调研报告.md              │ ← 可多人、多文件
  │                                   │
  │  输出                              │
  │    → 人C: 分析报告_v2.md           │
  │    → 人E: 数据看板链接              │ ← 可多人、多文件
  │                                   │
  │  版本：v2（基于上游 v1 + v3 合并）  │
  │  状态：✅ 已完成                   │
  │  [点击打开文件]                    │
  └──────────────────────────────────┘

箭头 = 文件传递关系
  ├── 人A ──数据汇总.xlsx──→ 人B  表示"人A 把文件传给 人B"
  ├── 人B ──分析报告_v2.md──→ 人C
  └── 一个节点可以有多个入箭头和多个出箭头

网状图（Obsidian Graph View 风格，后期开发）
  ├── 仅展示文件节点，不展示人
  ├── 连线表示文件的上下游依赖关系（谁生成了谁）
  ├── 点击文件 → 跳转到对应的流程图节点
  └── 核心用途：出问题后逆推责任链，定位哪个环节出了岔子

版本追溯
  ├── 同一文件经不同人产生不同版本
  ├── 每个版本与对应节点绑定
  └── 节点展开可查看版本历史

排版 = 自动布局引擎
  ├── dagre 分层布局
  └── 节点大小自适应内容
```

### 3.2 用户场景

| 场景 | 现在的做法 | 这个工具的做法 |
|------|-----------|--------------|
| 项目文件协作管理 | 微信群/飞书传文件，靠人脑记谁改了什么 | 每个节点结构化记录→人→文件，版本自动关联 |
| 文件出问题追责 | 翻聊天记录问"谁改的最后一版？" | 沿文件流向逆推网状图，定位责任人+版本 |
| 新人接手项目 | 看一堆零散文件，理不清上下游关系 | 打开流程图一目了然，文件从哪里来、往哪里去 |
| 多版本文件管理 | 同一文件在多人间传来传去，版本混乱 | 每个节点绑定其产出的版本，版本历史可追溯 |
| 交付物验收 | 逐个文件检查状态 | 流程图标注状态，一眼看出哪些节点已完成、哪些卡住 |

## 四、技术方案

### 4.1 架构

```
┌─────────────────────────────────────┐
│           MCP Server                │ ← Hermes Agent 通过 MCP 生成/修改图
│    tools: create_diagram,           │
│           add_node, add_edge,       │
│           auto_layout               │
└──────────┬──────────────────────────┘
           │ JSON 指令
┌──────────▼──────────────────────────┐
│         tldraw (画布引擎)           │ ← 渲染 / 交互 / 撤销
│  ┌──────────────────────────────┐   │
│  │  Markdown Shape (自定义)     │   │ ← 渲染 .md 内容
│  │  文件名 | 图标               │   │
│  │  ----                        │   │
│  │  # 标题                      │   │
│  │  - 列表                      │   │
│  │  `code`                      │   │
│  │  ---                         │   │
│  │  [打开文件]                  │   │ ← 链接到本地路径
│  └──────────────────────────────┘   │
└─────────────────────────────────────┘
           │ 本地 / 自托管
     ┌─────▼──────┐
     │   nginx    │ ← 静态文件或 WebSocket
     └────────────┘
```

### 4.2 为什么选 tldraw 而不是 Excalidraw

| 对比项 | tldraw | Excalidraw |
|--------|--------|------------|
| 自定义 Shape | ✅ 官方 Shape API | ❌ 无，仅 JSON |
| 排版 | ✅ 智能对齐 + 文字精确 | ⚠️ 偏差大 |
| 嵌入方式 | React 组件 | iframe |
| 协作 | 原生 y.js | 需额外对接 |
| 社区活跃度 | Vercel 主力维护 | 好但生态增长慢 |

### 4.3 依赖

| 依赖 | 用途 | license |
|------|------|---------|
| tldraw | 画布引擎 | MIT |
| marked | Markdown → HTML | MIT |
| dagre | 自动布局 | MIT |
| React | tldraw 宿主 | MIT |

**核心代码量：约 500-800 行。** 不是大项目。

### 4.4 交付形态：单个 HTML 文件

MVP 是一个单独的 `index.html`，双击即可在浏览器中运行。

```
projects/flow-canvas/
├── index.html       ← 双击打开，直接在浏览器运行
├── style.css
└── script.js
```

工作原理：tldraw 打包成一个 JS 文件，塞进 HTML 里。不需要 Node.js，不需要 npm install，不需要服务器。

```
双击 index.html ──→ 浏览器 ──→ tldraw 画布 + Markdown 节点
```

### 4.5 集成路径（核心引擎不变）

从 MVP 到其他平台的路线：

```
双击 HTML（MVP）              ← 起点，用户零门槛
  │
  ├── 扔到 nginx 目录          ← 私服部署（一行 cp）
  │
  ├── Obsidian 插件            ← 把 HTML 作为 iframe 嵌入
  │
  ├── VS Code 扩展             ← 把 HTML 作为 Webview 加载
  │
  └── 进一步封装后端            ← 飞书 / 协作 / WebSocket
```

**关键原则：无论套什么壳，中间 tldraw 画布 + 定制 Shape 完全不变。**

| 集成 | 实现方式 | 工作量 | 难度 |
|------|---------|--------|------|
| 私服部署 | nginx 托管静态文件 | 0 | 最简单 |
| 浏览器 | 直接打开 HTML | 0 | 默认形态 |
| Obsidian | Community Plugin（iframe 嵌入画布） | 1-2 天 | 中等，API 成熟 |
| VS Code | Extension（Webview Panel） | 1-2 天 | 中等，API 成熟 |
| 飞书 | 自建应用 + 消息卡片 / 网页标签 | 2-3 天 | 较高，但文档全 |

### 4.6 用户需要的能力

用户（你）不需要任何 Web 开发知识。

**你需要的全部能力：**
```
1. git clone 仓库
2. 双击 index.html     ← 打开浏览器
3. 告诉我哪里不对        ← 需求决策 + 视觉验收
4. (可选) cp 到服务器   ← 部署
```

**我处理的部分（你不需要接触）：**
```
React + tldraw 集成      ← 前端渲染引擎
Shape API 定制           ← Markdown 节点、文件链接节点
dagre 布局算法            ← 自动排版
MCP 协议对接              ← 我能用 Hermes 生成图
CSS / UI 样式            ← 美观度
插件/扩展代码             ← Obsidian / VS Code / 飞书
```

**唯一代价：** 浏览器出现渲染 bug 时，你需要刷新页面验证修复。多一个来回，但完全走得通。

### 4.7 工作量估算

| 阶段 | 内容 | 时间 |
|------|------|------|
| 技术验证 | 单 HTML 文件，tldraw + Markdown Node + 文件链接 + dagre | 1-2 天 |
| MCP 接入 | 两个 tool（create_diagram, auto_layout） | 0.5 天 |
| 打磨 | 自动排版调优、暗色主题、导出 | 2-3 天 |
| Obsidian 插件 | iframe 嵌入 + 文件系统桥接 | 1-2 天 |
| VS Code 扩展 | Webview 包装 | 1-2 天 |
| 飞书集成 | 自建应用 + 后端服务 | 2-3 天 |
| 协作 | y.js WebSocket 多人编辑 | **可后做** |
| 维护 | 依赖稳定，几乎无长期负担 | 接近零 |

**开发节奏建议：先浏览器 MVP 跑通，再决定是否做集成。** 集成都不是前置条件。

## 五、风险与未定项

| 风险 | 级别 | 缓解 |
|------|------|------|
| dagre 布局对复杂图效果未知 | 中 | MVP 阶段拿真实场景测试 |
| 文件链接的权限/安全问题 | 低 | 本地工具，不走网络 |
| tldraw 上游 Breaking Change | 低 | 定制层薄，升级成本低 |
| 多人协作复杂度 | 高 | 推迟到 MVP 验证后 |
| 用户是否需要"拖拽编辑" | — | 需确认：AI 生成为主 vs 手调为主 |
| 用户无 Web 开发经验 | 无影响 | 代码全部由 Hermes 编写，用户仅验收 |
| 飞书集成需要管理员账号 | 中 | 需用户操作一次，可排到最后 |
| Obsidian / VS Code 商店发布审核 | 低 | 可先用本地安装，不急上架 |

## 六、MVP 确认（2026-06-01）

### 6.1 MVP 功能范围

```
everything-flow /           ← 项目名
├── index.html              ← 双击打开

功能：
├── 节点（Markdown 段落渲染）
│   ├── 一个可渲染 MD 的内容区（核心）
│   └── 可选模板字段（通过表单添加）：
│       ├── 责任人
│       ├── 任务描述
│       ├── 输入文件列表（可增删行）
│       ├── 输出文件列表（可增删行）
│       ├── 版本号
│       └── 状态（默认几个 + 可自定义添加）
├── 箭头
│   ├── 标签 = 文件名
│   └── 可隐藏文件名显示
├── 拖拽排版
└── 保存/加载为 JSON 文件

不做：
├── 网状图（后期）
├── 文件双击打开（后期）
├── AI/MCP 控制（后期，预留接口）
├── Obsidian / VS Code / 飞书集成（后期）
└── 多人协作（后期）
```
