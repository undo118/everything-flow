# Hermes 工作规范（Everything Flow 项目）

## 核心原则

### 1. 已通过的工作绝不修改
- 用户确认通过（✅）的方案、代码、视觉效果，**禁止任何修改**
- 新增功能必须与已有功能完全隔离
- 新增情况必须用独立代码实现，不准重构共享逻辑

### 2. 只做用户明确要求的
- 用户说做什么就做什么，不多做不少做
- **禁止自己推导、扩展、补充**用户没说的内容
- 觉得有更好的想法？先问用户，用户同意才能做

### 3. 一步一确认
- 每次只做一小步，做完让用户看
- 用户说「对了」才能继续下一步
- 用户说「不对」就修到对

### 4. 不碰项目源代码
- 未获明确授权，**不允许修改项目源代码**
- 演示/效果图只放到 `temp/` 目录
- 效果图用独立 HTML 文件，不依赖项目代码

### 5. Plan 是圣旨
- 写 plan 放到 `plans/pending/`，等用户审查
- 用户通过后移到 `plans/approved/`
- 严格按照 plan 执行，不偏离
- 觉得 plan 有问题？问用户要不要改，不改就照做

### 6. 代码和数据隔离
- 每个功能/情况的代码完全独立
- 不使用共享逻辑函数（避免修一个坏一片）
- 新功能用新文件，不修改已有文件

## 工作流程

1. 用户提出需求
2. 理解确认（复述一遍，让用户纠正）
3. 写 plan（如需）→ `plans/pending/`
4. 用户审查 plan
5. 实施（一次一步）
6. 用户确认 → 标记 ✅
7. 进入下一步

## 箭头正交化专项工作流（2026-06-09 约定）

> **本次正交路由开发使用"数学公式 → HTML 效果 → 逻辑理解 → 工程实现"四步法。**

### 步骤顺序（不可逆）

```
① 用户用数学公式说明一种情况
        ↓
② Hermes 在 temp/ 下建 standalone HTML 渲染该情况
        ↓
③ 用户看效果
   ├─ 不满意 → 调公式/调渲染 → 回到 ②
   └─ 满意 ✅ → 进入 ④
        ↓
④ Hermes 理解并复述背后的逻辑
        ↓
⑤ 用户确认逻辑理解正确
        ↓
⑥ 进入下一种情况（回到 ①）
        ↓
...
所有情况验收通过后
        ↓
⑦ 写 plan → 用户在 plan 上确认 → 动工程文件
```

### 专项红线

- **不跳过步骤**：不接受"先全部渲染出来再看"，必须一个一个来
- **不改已通过**：已通过 ✅ 的情况，其 HTML 渲染代码不能因后续情况而修改
- **不提前写逻辑**：在全部情况验收通过之前，不推导通用公式、不写路由函数、不碰 `src/`
- **不猜用户意图**：公式没看懂就问，不自己脑补
- **全部情况放在同一个 HTML 文件中**，但每个 case 的代码必须完全独立隔离——修改 case N 时不得改动 case 1 到 case N-1 的任何代码（包括不共享变量、函数、数据）
- **case 间物理隔离**：每个 case 用独立的 `<div>`、独立的 SVG 渲染代码、独立的样式变量，不准抽公共函数

## 禁止清单

- ❌ 修改已通过的内容
- ❌ 自己做主扩展功能
- ❌ 一次性做多个步骤不确认
- ❌ 修改项目源代码（无授权时）
- ❌ 用共享逻辑函数关联不同功能
- ❌ 猜用户意图代替询问
- ❌ 在全部情况验收通过前写路由逻辑
- ❌ 跳过"逐个渲染确认"直接实现
